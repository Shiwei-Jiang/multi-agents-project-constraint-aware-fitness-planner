Constraint-Aware Fitness Planner

A runnable, inspectable planning workflow for non-clinical fitness support that can pause on ambiguity, expose tradeoffs, coordinate bounded agent handoffs, and hand the user a shareable reviewed plan instead of only a demo trace.

Roles: Intake, Constraint Checker, Plan Composer, Review & Adaptation Evidence: traces, state, saved scenario outputs Scope: non-clinical decision support
Open Evaluation Evidence View

This interactive UI mirrors the same workflow logic used by the reproducible evaluation runner in `scripts/run_evaluation.mjs`.

1. Intake

The user provides a bounded profile that the system normalizes before any planning step is allowed to proceed.

Clarification and prioritization pause the workflow until the user updates the intake and clicks Continue After Update. The adaptation branch now accepts structured post-acceptance execution feedback before reopening the workflow.

Fill in the intake fields, then run the workflow to generate a formal plan trace.

Post-Acceptance Feedback Input

Use this input after accepting a reviewed plan. It lets the adaptation branch react to real execution feedback instead of only a fixed demo event.

Human Resolution Options

When the system pauses for an infeasible tradeoff, these workflow-owned options let the user resolve it explicitly instead of relying on a hidden controller choice.

Trust and Scope Cues

  • Non-clinical only: the artifact does not diagnose, prescribe, or interpret medication.
  • Ambiguity is surfaced explicitly instead of being filled in with confident guesses.
  • Conflicting tradeoffs are routed back to the user when the system should not decide for them.
  • The browser artifact is local-only and uses visible session state rather than hidden persistent memory.
